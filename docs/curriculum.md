# 课程路线与学习协议

## 目标能力

学完后，能够从查询请求一路追踪到数据页和日志；解释事务在并发、崩溃和副本故障下的保证；阅读 MySQL 8、PostgreSQL、TiDB 的架构材料和关键代码；针对给定负载提出可验证的索引、事务、恢复或分布式设计方案。

课程不以“读完源码”为目标。源码阅读服务于解释具体机制，且每次只跟一条端到端路径。

## 阶段路线

| 阶段 | 驱动问题 | 被逼出的概念 | 实验/产物 |
|---|---|---|---|
| 0. 存储起步 | 如何保存并查回一条记录？ | 文件、页、序列化、缓冲 | 手写追加文件与页布局 |
| 1. 查找与索引 | 扫全文件为何逐渐不可接受？ | 有序索引、B+ 树、哈希、聚簇与覆盖 | 实现简化 B+ 树，比较读写代价 |
| 2. 查询执行 | SQL 为什么可能用错索引？ | 解析、逻辑/物理计划、连接算法、统计信息 | 对照 EXPLAIN 与实际执行 |
| 3. 原子性与恢复 | 写到一半断电怎么办？ | WAL、redo/undo、检查点、提交持久性 | 简化日志恢复模拟器 |
| 4. 并发与隔离 | 两个事务同时修改时，什么结果算正确？ | 锁、死锁、隔离异常、串行化 | 构造调度历史并判定异常 |
| 5. MVCC | 读为何不总是等写？旧版本何时能删？ | 快照、可见性、版本链、垃圾回收 | 跟踪事务快照与版本可见性 |
| 6. 引擎对照 | 同样的 SQL 为何内部路径不同？ | InnoDB 与 PostgreSQL 的页、索引、WAL/MVCC 取舍 | 沿一次查询和一次提交读文档/源码 |
| 7. 复制与故障 | 多副本怎样避免确认写丢失？ | 主从、同步/异步、复制日志、故障检测 | 注入延迟和节点故障观察行为 |
| 8. 共识 | 网络分区时怎样安全地决定日志顺序？ | 领导者、任期、选举、日志匹配、提交规则、线性一致性 | 小型 Raft 日志模型/故障轨迹推演 |
| 9. 分布式 SQL | SQL 如何落到分片，并跨分片提交？ | 键范围分片、路由、2PC、时间戳、重试 | 追踪 TiDB 一次事务路径 |
| 10. 规模化的代价 | 分片/复制带来哪些新瓶颈？ | 热点、重平衡、GC、安全性/活性、可观测性 | 设计容量与故障演练方案 |

## 每章的循环

1. **问题**：给定具体负载或故障，先写出期望行为。
2. **尝试**：用已有知识提出方案，画数据结构或事务时间线。
3. **压力**：找出方案失效的输入、并发交错或故障时刻。
4. **发现**：从失败轨迹里提取必须满足的不变量。
5. **抽象**：给这个不变量或机制命名，再写清前提和边界。
6. **实现**：先做小模拟，再将机制映射到指定数据库版本。
7. **验证**：用新例子应用、推导反例，并从基础重建方案。

## 掌握标准

概念分别记录四种能力，不用章节完成度代替掌握度：

| 能力 | 自测 |
|---|---|
| 解释 | 不看材料说明机制解决什么问题，以及不解决什么问题 |
| 推导 | 从不变量/规则推出结果，例如判定一条日志何时可提交 |
| 应用 | 在新负载或故障历史中预测行为，并说明依据 |
| 重建 | 忘掉术语后，从旧方案失败处重新导出所需机制 |

每题先给自己两轮提示机会：方向提示、局部观察；仍卡住再看关系提示和完整解答。每三到四章做一次概念图重建。

## 版本与引用约定

每个实现专题开头记录数据库、精确版本和对应官方文档/源码路径。原理描述与实现事实分开写。遇到版本差异，优先以对应版本官方资料和可复现实验为准，不将特定版本细节推广成普遍规律。
