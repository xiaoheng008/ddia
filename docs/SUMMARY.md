# 学习路线

本教程按“下一个问题从哪里来”排序。路线是为了学习而重建的因果路径，不是技术史的年代顺序。

```text
持久化记录
  -> 页与缓冲：以块为单位组织存储和 I/O
  -> 索引：减少定位数据所需读取的页
  -> 查询执行：把声明式 SQL 变成算子计划
  -> WAL 与恢复：崩溃后恢复到合法状态
  -> 锁与隔离：并发操作仍满足事务语义
  -> MVCC：让读写在版本与快照上协作
  -> 单机引擎对照：理解 InnoDB 与 PostgreSQL 的具体取舍
  -> 复制：维护多个副本并定义确认语义
  -> 共识：故障和网络延迟下安全决定日志顺序
  -> 分片与分布式事务：将 SQL 扩展到多节点
  -> TiDB 路径：连接 SQL 层、PD、TiKV、Raft 与事务协议
  -> 从最初的持久化问题重建整个系统
```

## 后续阶段

| 阶段 | 范围 | 核心压力 |
|---|---|---|
| 2 | SQL 解析、执行器、连接算法、代价优化 | 同一条查询为什么能有多种执行方式？ |
| 3 | WAL、检查点、崩溃恢复与持久性 | 更新到一半掉电，如何判断哪些修改生效？ |
| 4 | 锁、隔离级别、死锁、MVCC 与版本回收 | 并发事务如何安全交错，旧版本何时可清理？ |
| 5 | InnoDB 与 PostgreSQL 内核对照 | 相同需求下，不同存储模型怎样改变实现？ |
| 6 | 复制、故障模型、Raft 与共识 | 节点失联时如何避免副本各自决定不同结果？ |
| 7 | 分片、两阶段提交、时间戳与重试 | 一个事务跨越多个共识组时如何完成？ |
| 8 | TiDB 架构与端到端事务路径 | SQL 请求如何经过 TiDB、PD、TiKV 和 Raft？ |
| 9 | 重平衡、热点、GC、运维与最终重建 | 扩展能力带来了哪些新瓶颈和故障面？ |

每个阶段结束后，重建“前一概念为什么不够、下一概念如何补足”的关系。章节和实现对照会随内容完成逐步加入导航。
