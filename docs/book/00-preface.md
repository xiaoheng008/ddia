# 序言：把数据库知识学成可以重建的东西

## 问题

如果能背出 B+ 树、WAL、MVCC、Raft 的定义，却无法解释它们各自要解决什么故障或性能瓶颈，这算理解数据库系统了吗？本教程把目标定得更高：遇到新负载或故障时，能够从数据与请求的行为重新推出所需机制。

## 尝试

设想你要实现一个很小的服务：记录用户资料，支持按主键查询；服务重启后数据不能丢；多个客户端可以同时读写；未来还希望机器坏掉后服务继续工作。

先想一想：一个文件够不够？把文件按页组织后，查询会自动变快吗？加索引后，崩溃恢复会更简单吗？复制到多台机器后，确认写入又意味着什么？

## 这本教程怎样前进

每遇到一种结构，我们都会依次问：问题是什么？已有办法能做到什么？什么负载或故障暴露了限制？从失败中能提取什么必须遵守的不变量？新抽象提供了什么能力，又制造了哪些代价？

概念会在压力出现后再命名。直觉负责找到方向，明确假设和推导负责保证严谨。实验用于观察机制；数据库文档和源码用于核对具体实现。我们会标出通用原理和特定版本事实的边界。

这条路线是认知上的重建，不声称复现数据库技术史的真实先后。MySQL 8、PostgreSQL、TiDB 用作实现对照；它们并不是同一设计的不同包装。

## 重建目标

学到后面，你应当能从一次 SQL 请求出发，追到执行计划、索引页、事务版本、日志和副本提交；也能从一次崩溃或网络分区出发，指出系统依赖哪些不变量来恢复和继续服务。

贯穿全书的问题是：

> 如果前一个世界已经存在，为什么还需要这个新概念？
