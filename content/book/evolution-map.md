这是一条教学上的概念重建路径，不是数据库技术的历史年表。主线始终追问：已有能力解决了什么，新的压力又从哪里出现？

## 主链：从记录到可靠事务

```text
保存记录
  → 文件与页：让数据跨进程、跨重启存在
  → 页面布局与缓冲池：减少磁盘访问并管理内存副本
  → 搜索变慢：索引、B+ 树与哈希索引
  → SQL 组合爆炸：逻辑/物理计划、统计信息与代价估算
  → 计划必须实际产出结果：扫描、过滤、投影与连接算子
  → 行数很大或有排序/哈希：按需流水线与阻塞边界
  → 更新到一半遇到故障：WAL、检查点与崩溃恢复
  → 多请求交错：锁、隔离级别与并发控制
  → 跨行约束仍会被写偏斜破坏：串行化保证与冲突检测
  → 长报表与写入互相等待：MVCC、快照可见性与版本回收
  → 同一条 UPDATE 落到不同物理路径：InnoDB 聚簇索引 vs PostgreSQL heap/TID
  → 单机容量/可用性不足：复制、分片与故障模型
  → 主库确认后仍可能丢写：异步/同步复制确认与故障切换
  → 网络分区时领导者可能失联：Raft 任期、多数派、日志匹配与安全提交
  → 一个 SQL 事务跨越多个共识组：两阶段提交、协调者恢复与提交时间戳
  → 节点可能失联或重启：复制日志与状态机复制
  → 多副本要安全选主并提交：Raft/Paxos 类共识、任期与多数派
  → 跨分片事务：分布式提交、时间戳与冲突处理
  → 延迟和运维复杂度上升：一致性、可用性、扩展性之间的工程权衡
```

## 支线：查询如何变成执行

```text
声明“要什么” (SQL)
  → 解析与名称绑定
  → 逻辑计划（关系运算）
  → 统计信息与代价模型
  → 物理计划（扫描、连接、排序）
  → 执行器与迭代/向量化
  → I/O、内存、并行度与结果
```

优化器并非“猜最快 SQL”：它在统计信息、代价估计和可用算子约束下挑选计划。估计误差会把局部选择放大成全局性能问题。

## 横切问题

```text
数据表示：行式/列式、编码、压缩、页和日志
并发语义：锁、MVCC、隔离级别、死锁
持久性：WAL、检查点、刷盘、备份与恢复
可观测性：执行计划、锁等待、日志、指标和追踪
演进能力：DDL、在线变更、兼容性和复制协议
```

## 分布式主链的因果细化

```text
复制数据提高容错/读能力
  → 异步复制可能丢失已确认写，副本读到旧值
  → 需要规定确认语义和副本顺序
  → 复制日志把更新表达成有序命令
  → 节点故障、网络分区、旧主复活带来冲突
  → 共识为日志项的提交顺序提供安全规则
  → 共识只解决复制状态机的排序/提交，不自动解决 SQL 事务、跨组原子提交或全局时间
  → 分片后还要处理路由、跨分片事务、重分区、热点和时钟/时间戳
```

重点区分：

- **复制**是维护多个副本；**共识**是在故障和消息延迟下让参与者对某些值/日志前缀作安全一致的决定。
- **Raft/Paxos**描述共识协议族；**Raft group/共识组**是某系统中运行此类协议的副本集合。
- **共识提交**不等于“整个数据库事务提交”。一个 SQL 事务可能涉及多个共识组，需额外的事务协调协议。
- **一致性**要说清语境：线性一致性、可串行化、因果一致性等并非同一个保证。

## 系统对照：用来问问题，不用来背名词

| 压力点 | MySQL 8（InnoDB 为重点） | PostgreSQL | TiDB |
|---|---|---|---|
| 单机数据与索引 | InnoDB 聚簇索引、二级索引、页与缓冲池 | heap tuple、索引访问方法、共享缓冲区 | SQL 层逻辑表映射到分布式键值数据 |
| 并发与版本 | InnoDB MVCC、undo、锁 | MVCC tuple、快照、VACUUM | 分布式事务版本与时间戳；底层由 TiKV 承载 |
| 崩溃恢复/持久化 | redo/undo、检查点等 InnoDB 机制 | WAL、检查点与恢复 | TiKV Raft 日志/持久化，加上事务协议层 |
| 分布式扩展 | 常见部署依赖复制/分片组件，产品形态需按具体方案核实 | 常见部署依赖扩展/复制方案，非内核自带透明分布式 SQL | 分布式 SQL 架构；PD 管理集群元信息/调度，TiKV 以 Raft 复制 Region |
| 本课程关注 | 事务存储引擎与 SQL 层边界 | 对照 MVCC、优化器、WAL、扩展接口 | 从 SQL 到分布式 KV、调度、共识和事务路径 |

表格是高层索引，不是实现规格。各章节会核对所讨论版本的官方文档和源码。

## 依赖图

```text
页/记录 ──→ 缓冲池 ──→ I/O 与缓存策略
   │             │
   ├──→ B+树/索引 ──→ 查询执行与优化
   │
   └──→ 更新 ──→ WAL/恢复 ──→ 事务持久性
                         │
SQL/约束 ──→ 并发事务 ───┼──→ 锁与 MVCC ──→ 隔离语义
                         │
                         └──→ 复制日志 ──→ 共识 ──→ 分片/分布式事务
```

其中很多模块互相施压：例如 MVCC 让读写冲突减少，却带来旧版本回收；索引加速查询，却增加写放大与恢复工作；共识提高副本状态的一致性，却增加写延迟并不保证跨分片原子性。
